## Why

Today, the desktop `chat:*` router already powers two UIs over a shared `subChatId`: the **classic chat** (messages + plan/review sidebars) and the **OpenSpec change editor** (sidebar chat + spec/proposal/tasks views). The discriminator is a single column on `subChats`: `openspecChangeId` (set ⇒ editor; null ⇒ classic chat). This works well, but the chat content is always the *built-in Claude SDK orchestrator*.

We want to add a third class of chat content: an **embedded native CLI** (Claude Code CLI, Codex CLI, and others later) running inside a terminal in place of the message list, while keeping the same `chat:*` lifecycle, the same sidebars (plan, review, diffs), the same prompt input at the bottom, and the same dockview shell. The native CLIs should bootstrap with our MCP server already injected so they can write plans/reviews back into the existing per-subchat artifact files, and the chat input should pipe through the terminal's `write` API so users still type one prompt and "Send" — even when the underlying agent is a TUI process.

This unifies three previously disjoint surfaces (chat, openspec editor, terminal) under one `chat:*` lifecycle and lets the user pick a harness (built-in vs Claude/Codex CLI) per workspace from the New Workspace UI and per panel from the dockview "New" menu.

Because embedded CLIs introduce out-of-process state (a real `claude`/`codex` child, its config file, an MCP bearer/port) that the desktop process does not own end-to-end, we also need an explicit story for **session resilience and per-subChat isolation**: every subChat must survive an app restart cleanly, each subChat must be a closed-loop unit (no plan/review/MCP/state bleed across subChats), and the user needs a one-click way to force-recover when something gets stuck. An audit of today's code (PTYs die with the app and only xterm scrollback is persisted; MCP port + bearer regenerate on boot which staless any pre-written CLI config files; file watchers are workspace-keyed not subChat-keyed; cross-subChat mutation guards in `sub-chat-store.ts` are warn-only; plan/review writes are a tmp-rename pair without fsync; no per-chat hard-reset affordance exists) shows enough gaps that we are folding the fix into this same change rather than letting it drift.

## What Changes

- Add a **`harness`** column to `subChats` with values `builtin` (default), `claude-cli`, `codex-cli`. Combined with the existing `openspecChangeId`, it becomes the discriminator for which content surface renders inside a chat panel. **Harness is immutable for the lifetime of a subChat** — no UI, tRPC procedure, or migration may switch it; switching agents requires creating a new subChat. This is what makes per-subChat plan/review write-arbitration safe.
- **Per-harness identifier icon** on the dockview tab AND in the chat-panel header (Claude logo for `claude-cli`, Codex logo for `codex-cli`, existing chat icon for `builtin`), so users can tell at a glance which agent process drives each chat. The icon registry is reused by the dock "New" menu and the wizard's Agent dropdown.
- Introduce a **chat surface router** in the renderer (`ChatPanel`) that maps `(harness, openspecChangeId)` → one of three content components: classic messages, openspec editor, or embedded terminal. Sidebars (plan, review, diffs) and the bottom prompt input are surface-agnostic.
- Refactor the **terminal feature** so a single component can be used standalone (existing "New Terminal" panel) *or* embedded inside a chat panel as the agent surface. Terminal sessions gain: declarative bootstrap (cwd, env, command, optional initial input), idle detection, and an explicit `sendInput`-from-code path used by the chat input and sidebar action buttons (Approve, Build Plan, Fix Review Issues). Verify TUI robustness (256-color, truecolor, UTF-8, alternate screen, cursor positioning, mouse) so progress bars and full-screen TUIs render correctly.
- Add a **CLI harness bootstrap** layer that, given a subChatId and harness, launches the right binary (`claude` or `codex`) with: our MCP server URL + bearer pre-injected as a config (Claude config file / Codex `--mcp-config`), the `subChatId` exposed via env (`CHURRO_SUBCHAT_ID`) so MCP tool calls land on the right artifact files, and a per-CLI startup script (e.g. send `/model …` then a prompt).
- Extend the existing **MCP server** (`read_plan`, `read_review`, `write_review`) so the per-subchat factory can be reached over HTTP transport with the subChatId derived from a request header/env that the bootstrap injects. Reuse existing artifact-file watch/invalidate plumbing so plan/review sidebars update when the CLI writes them.
- Wire the **chat input** to dispatch differently based on harness: `builtin` → existing agent send; `claude-cli`/`codex-cli` → `terminal:write` with a newline and optional slash-command prefix (e.g. `/model opus\n<prompt>\n`).
- Add **dockview "New" menu** entries for `New Claude CLI` and `New Codex CLI` (alongside `New Chat`, `New Terminal`, `New OpenSpec Change`). Add a **settings** mechanism that decides which entries appear pinned in the toolbar vs. hidden in the dropdown.
- Keep the existing **New Workspace wizard** `vibe-coding | spec-driven` card selector exactly as it is today — it continues to pick between classic chat and openspec change editor with no UI change. **Add** a new sibling **Agent** dropdown (`builtin | claude-cli | codex-cli`) at the same level as the project / worktree / branch selectors, so the two axes — *what surface the chat is about* (existing cards) and *which agent process drives it* (new dropdown) — are picked independently.
- Apply the same surface router to the **OpenSpec change editor's sidebar chat**: it can host either the built-in chat or the embedded CLI terminal, with action buttons (Approve plan, Apply, Archive) routing through `sendInput` when the harness is a CLI.
- **App-restart resumption** for every harness:
  - Built-in chat: already works (messages from SQLite, in-flight stream state is dropped). We codify that contract.
  - Embedded CLI: **cold restart, always**. Respawn the PTY lazily when the chat panel becomes active after restart, **always re-rendering the CLI bootstrap config files at spawn time** using the current MCP port + bearer (never reuse stale config from a previous app session). No `--resume`-style flag is passed; no TUI-output parsing is attempted to recover a CLI session id. xterm scrollback is restored from the existing per-pane history file so visual continuity is preserved, and continuity of *work* is delivered via the per-subChat plan/review files that survive on disk — the new CLI session can read them through MCP on its first turn.
  - Openspec editor: same as built-in for the sidebar chat; editor side-state (current section) is restored from the panel's persisted params.
- **Per-subChat isolation** hardening: MCP HTTP `/sub/<id>/` route is the only way external CLIs reach our tools (root route stays in-process / built-in only); unknown `<id>` is rejected with a structured error; bearer is validated on every route; plan/review files live under `<userData>/sub-chats/<id>/…` and are written via a 3-phase atomic protocol (`.tmp` → `fsync` → `rename` → write `.meta.json` last); a single-writer claim prevents two panels/windows from driving the same subChatId concurrently (second opener falls back to read-only with a banner).
- **Hard-reset** action per chat panel header, available for every harness:
  - Built-in: abort the in-flight stream, drop transient queue state, message history left intact.
  - CLI: SIGTERM→SIGKILL the PTY, leave or clear scrollback (configurable), re-run the bootstrap (rewrites the per-subChat CLI config with the current bearer/port) and respawn.
  - Openspec editor: same as built-in, plus reset the editor's transient view state (which section is open).
- **Stuck-session detection**: heuristics (PTY exited unexpectedly within first N seconds, MCP `read_plan` 500s repeatedly, agent stream silent past timeout) surface a **stall icon** in the chat-panel header (distinct from the harness icon). Clicking the stall icon expands a non-modal banner naming the heuristic with a "Hard-reset session" CTA — the same action exposed in the panel menu. The app **never** auto-restarts; the user decides whether to wait or reset.
- **Harness persistence through dockview re-mounts**: the `harness` discriminator MUST travel on the panel-entity that dockview hands back on drag-and-drop, tear-out, and layout deserialization, so a `claude-cli` or `codex-cli` panel never flashes (or sticks) on the classic builtin surface during a re-mount. The renderer-side panel-entity type carries `harness`; every entity-construction site populates it; the chat-panel router prefers `params.harness` over any store/query fallback whose hydration may lag the mount.
- **BREAKING**: `subChats` rows created before this change will be backfilled with `harness = 'builtin'`; no behavior change for existing chats. New chats default to whatever the workspace's default harness is.

## Capabilities

### New Capabilities

- `chat-surface-router`: the rule that maps a subChat's `(harness, openspecChangeId)` to one of three content surfaces (classic messages, openspec editor, embedded terminal) inside a `chat` dockview panel, while keeping sidebars and the prompt input shared. Includes the chat-input dispatch rule (agent send vs `terminal:write`).
- `cli-harness`: the bootstrap contract for embedding native coding-agent CLIs (Claude Code, Codex, future). Covers binary discovery, MCP config injection, env propagation of `subChatId`, optional startup input, idle detection, lifecycle (start/restart/stop) tied to the chat panel and subChat lifecycle.
- `terminal-embedding`: the requirements that let the existing terminal feature be reused as both a standalone panel and an embedded chat surface — declarative bootstrap, programmatic `sendInput` from UI buttons and the chat prompt, TUI-grade fidelity (encoding, color, alternate screen, cursor control, resize), and per-session lifecycle scoped to a subChat.
- `harness-aware-workspace-creation`: the New Workspace wizard adds a new agent-harness dropdown alongside the existing project / worktree / branch selectors, persists the choice on the new chat's first subChat, and is fully independent of the unchanged `vibe-coding | spec-driven` card selector that drives classic-vs-openspec.
- `dock-new-menu-customization`: the dockview "New" menu lists all surface combinations (chat, claude-cli, codex-cli, terminal, openspec change) and a setting controls which are pinned to the toolbar vs hidden in the overflow dropdown.
- `session-resilience-and-isolation`: the contract for surviving app restarts and for keeping each subChat a closed-loop unit. Covers per-harness restoration on boot, lazy CLI respawn with fresh bootstrap config files, MCP path-scoped routing enforcement (unknown subChatId rejected; bearer validated on every route), atomic 3-phase writes for plan/review artifacts with orphan-`.tmp` sweep on boot, single-writer claim per subChatId (second opener falls back to read-only), per-panel hard-reset action available for every harness, and stuck-session detection with an actionable in-panel recovery banner.

## Impact

- **Schema**: new `harness` column on `subChats` (TEXT NOT NULL DEFAULT 'builtin'). Enum (`'builtin' | 'claude-cli' | 'codex-cli'`) enforced at the Zod boundary + the tRPC immutability guard on UPDATE — SQLite cannot ALTER ADD a CHECK without a table rebuild, so the DB itself does not carry one. New Drizzle migration following the multi-statement separator + monotonic `when` rules in AGENTS.md.
- **tRPC routers**: `chat:*` gains optional `harness` in create-subchat input; `terminal:*` gains a typed `bootstrap` shape on `createOrAttach` (already accepts cwd/cmd; we formalize MCP-config wiring and `initialInput`). MCP HTTP transport gains a per-request `subChatId` resolution path.
- **Renderer**: `ChatPanel` gets the surface-router branch; `chat-input-area.tsx` gains a harness-aware send dispatcher; new embedded-terminal chat surface component; plan/review sidebars stay as-is but their action buttons learn to call `sendInput` in CLI mode; dockview "New" menu and settings page gain new entries; `new-workspace-explorer.tsx` (or sibling) gains the harness dropdown.
- **Main process**: `apps/desktop/src/main/lib/mcp/` gains a per-request subChatId resolver; `apps/desktop/src/main/lib/terminal/` gains explicit bootstrap + idle-detection hooks; CLI binary discovery (PATH lookup, version check) added under `apps/desktop/src/main/lib/cli-harness/` (new folder).
- **Settings/persistence**: new settings keys for pinned dock-new-menu entries and default workspace harness. New on-disk layout `<userData>/cli-bootstrap/<subChatId>.<harness>.<ext>` for the per-CLI config files written at every spawn (and overwritten — never reused stale).
- **Resilience surface**: per-panel hard-reset action and stuck-session banner in the chat header; in-memory single-writer claim registry in the main process keyed by subChatId; orphan-`.tmp` sweep at app boot under `<userData>/sub-chats/<id>/`; `terminal:*` gains an `exitedUnexpectedly` event used by the renderer to surface the banner.
- **External dependencies**: assumes user has `claude` and/or `codex` installed locally on PATH (no bundling). We add a discovery + actionable error if missing.
- **Docs**: `apps/desktop/AGENTS.md` updated to describe the surface router, harness column, and CLI harness bootstrap. Root `AGENTS.md` unchanged.
- **Out of scope (excluded)**: bundling/auto-installing the Claude or Codex CLIs; supporting harnesses other than `builtin`/`claude-cli`/`codex-cli` in this change; cross-host/remote terminals (still local PTY only); rewriting plan/review sidebar internals (only their action-button dispatch changes); extracting a separate "harness" service in the daemon (`apps/daemon`) — daemon work deferred. **Out of scope for resilience**: preserving in-flight built-in stream state across app restarts (still drops to last persisted message); attempting to migrate a stuck CLI session's internal context (we always cold-restart the CLI); cross-machine ownership coordination of a subChatId (single-writer claim is in-process only); preserving live CLI scrollback verbatim across hard-reset (we keep xterm scrollback unless user opts to clear it, but the PTY itself is always fresh).
